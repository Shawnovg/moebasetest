Analysis design · MoE_Analysis.ipynb

Four ways to look inside each step

1 · Linear probing

A linear read-out of the state after every step: label, region bits r₁..r₄, each clause’s 64-world truth table, top operator. Random-init model as control.

2 · Activation patching

Clean and corrupt inputs differ in one token that flips the label. Copy clean states into the corrupt run at one step and one position group.

3 · Sparse autoencoder

512 features on the final <cls> state, about 15 active per input. Does any single feature track a logic concept?

4 · Ablations, as the authors ran them

Also: halting-threshold sweep τ, MoM forced SKIP and module knockout, and retrained variants (MIM sign, load balancing, no halting, E = 1).

Probes: 8,000 training states, 3,000 test, 2,000 long-formula states per model · patching: up to 500 minimal pairs · ablations: 2,000 test examples.

All analyses use step hooks added to the models: they are called on the embeddings and after every block application, and are off during training. For halting SUT models the state recorded at step i is the soft-halted state, the one the classifier would read if computation stopped there. Probing: linear probes trained on states from training examples, evaluated on held-out test examples and on longer formulas. Balanced accuracy removes the class imbalance, so chance is 1/7 for the label and 0.5 per bit. The control is the same architecture with random weights (with SUT's tiny expert initialisation rescaled so the control actually computes random features). Patching: single-token edits, a variable swap or and/or swap, that change the gold label. We copy the clean run's states into the corrupt run at one step for one group of positions: , the edited token, the rest of the edited clause, the separator, the other clause. For halting models the whole ACT state is patched too. Patching all positions gives exactly 1, which validates the code. SAE: a ReLU sparse autoencoder with 512 features on the final state, L1 chosen so about 15 features fire per input. Ablations: run only the first k steps, sweep the halting threshold after training as in the SUT paper, knock out single experts, replace the router output by noise, and for MoM force SKIP or knock out modules. The retraining ablations come from the pilot runs.
